# C09 owner-capture checks — isolated implementation, not acceptance

The original full outcome remains independent real Node22 and Node24 package
rehearsals for the same archive, plus integration and reviewed acceptance controls.
Finish70% / NX30% do not change. No runtime install, inference, native-app launch,
canonical consumer integration or publication is authorized by this directory.

The existing pure matrix reader proves caller-supplied consistency only. This
owner utility additionally binds the separately retained capture's seven files:
capture, original intent, receipt, archive, expected contract, stdout and stderr.
The final owner command pins those exact bytes outside the capture itself.
Node24's current capture does not self-bind its intent or raw-log paths/lengths;
external owner pins close that gap without rewriting historical evidence.

The bounded read-only checker must:

1. Read only fixed filenames beneath an exact physical capture root, using
   regular nonlink files, size caps, descriptor identity checks and SHA-256.
   Unknown keys, malformed JSON and mismatched external pins refuse.
2. Validate closed capture/intent records and all no-authority flags, explicit
   process closure, zero exit, no signal/error/timeout/overflow/kill, positive PID,
   finite ISO time order and original timeout bound.
3. Compare exact command/cwd, Node major/version/path/hash and before/after
   identities; writer identity must match the fixed real writer. Reconcile every
   receipt/archive/expected descriptor with the actual retained bytes.
4. Bind source/stage/case/toolchain/negative-location maps from independently
   supplied current owner contract to intent, expected and receipt. No trusting
   a capture's self-generated expected pins as current source evidence.
5. Recompute raw-log hashes; stderr must be empty; stdout must be one JSON summary
   consistent with the receipt and lifecycle. Run the existing strict matrix
   reader against those exact receipt bytes; never create another rehearsal schema.
6. Keep outputs non-authorizing/unaccepted, scope TRUSTED_OWNER_CAPTURE_CONSISTENCY.
   These checks are not cryptographic source authentication, hostile-writer
   isolation, npm/tar executable provenance or descendant-drain attestation.

The live owner verifier is hard-pinned to the existing Node24 bundle. It must
report Node22 NOT_RUN and matrix INCOMPLETE until an actual separately reviewed
Node22 capture is supplied. Synthetic unit fixtures may exercise semantic
rejection and coherent positive cases; they cannot populate the real Node22 pin.
Full final acceptance will bind both real captures and construct one owner-pinned
two-runtime expected contract, not implicitly merge untrusted observations.

Root owns all files here. Daybreak-designated review supplied the six requirements;
actual served identity is unknown. Luna audits a separate history path read-only.
Source is reviewed before behavioral test execution. Retain failures and exact
before/after evidence; no percentage increase for this utility alone.
