## What changed

- The built-in Jev client uses Node's `https` module. `timeoutMs` may be from 1 second to 24 hours (default 60 seconds). v0.3.1 used global `fetch` and refused a timeout above 300 seconds; `fetch` also stopped a call after 300 seconds with no response headers. A `fetch` you pass to `createJevJudge`, `planWithJev`, or `createJevReviewer` is unchanged and keeps that limit. `planWithJev` and `createJevReviewer` pass `timeoutMs` through to that client when `judge` is `'typesafe'`. A `judge` function is used as is. The harder-task runner has `--jev-timeout-ms` for `--judge typesafe`; `--timeout-ms` stays the model-call timeout. The endpoint, request JSON, 1 MiB caps, and error codes are unchanged. Redirects are still errors. The key and the response body are still omitted from errors.
- The remote judge is opt-in. `planWithJev` and `createJevReviewer` call TypeSafe when `judge` is `'typesafe'` or a function you pass. `benchmarks/harder/run.mjs` calls it for `--plan` and `--jev-review` when `--judge typesafe` is passed. A `--judge` module still wins. v0.3.1, and the first unreleased runner change, sent when `TYPESAFE_API_KEY` was set and no judge was passed. With only that variable set, Nisi prints one stderr line (`TYPESAFE_API_KEY is set; the remote judge is off. Opt in with --judge typesafe or judge: 'typesafe'.`) and does not send. The advisor then throws `JEV_JUDGE_REQUIRED`. The runner exits before it creates the output file. A run without `--plan` or `--jev-review` stays on the local model and does not print that line. A `judge` other than a function or `'typesafe'` is `JEV_JUDGE_INVALID`. The line does not contain the key.
- A finished or partial harder-task file now records the token cap, timeout, reasoning effort, plan and review flags, task-set id, arms, repair budget (2), total deadline (600 seconds), judge source (`builtin`, `module`, or `function`), endpoint, package version, and Node version. It does not record the API key or the path of a judge module.
- A test reads `README.md`, `docs/benchmarks.md`, and `docs/local-models.md`. A table whose header contains accuracy, tokens/s, solved, or AUC must say `single run`, `runs:`, or `n =` in that section. Those three files have no such table missing the note. The package behavior is unchanged.

## What was not verified

- No call was made to `https://api.typesafe.ai`. The transport tests point the request function at a local HTTP server. They wait a few hundred milliseconds under a timeout longer than five minutes. They do not wait five minutes, and they do not exercise the public TLS host.
- No local model was loaded for a Nisi run. The open roadmap item, re-measuring the harder tasks on a set or model with headroom, stays `NOT_RUN`. A 10 November 2026 check on Louis-M5-Pro-MacBook-Pro.local found four LM Studio chat models already on disk, including `qwen3.8-27b`, but no unauthenticated loopback chat-completions endpoint that Nisi can call. The previously used port 1240 was not listening. A new `lms load` was not started, because earlier loads on that machine had crashed LM Studio, and existing model-server processes were left running. `benchmarks/harder/run.mjs` and `examples/local-model-workflow.mjs` were not invoked. See [the 10 November 2026 note](../reviews/2026-11-10-live-model-remeasure.md). The 2026-11-07 result files were not regenerated. Those files still omit the token cap and timeout, so the published table rows cannot be repeated from the file alone.
- The two nx05 revoke-scratch journals are not in this repository. They were not re-checked on 10 November 2026. Their earlier read-only check was `INVALID_JOURNAL` from `nisi validate`, and `reopen` reported `INVALID` / `RECORD` at line 3 (seq 2, `retained: false`, state `REVOKED`) because the stored fingerprint does not match the stored entry. The hash chain was intact. Those files were written before v0.2.1, which pruned a row without recomputing its fingerprint. They stay rejected. `reopen` and `nisi validate` now name that case `LEGACY_UNRETAINED_FINGERPRINT`. The remedy is to run the work again with v0.2.1 or later. The old bytes were not copied in, and the file is not repaired.
- The one-PC Windows note is still the v0.3.0 note. It was not repeated on 10 November 2026. CI on later commits covers GitHub-hosted Windows, which is not that PC.
- npm registry publication was not done.
