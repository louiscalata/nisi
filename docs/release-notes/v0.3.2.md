# Nisi v0.3.2

**Source version:** 0.3.2, prepared 18 November 2026.
**Previous tag:** `v0.3.1` at `be7a5c99338947baf130bc0d0364eef12cbef5cb` (PR #32), published 9 November 2026. The GitHub Release attaches `nisi-0.3.1.tgz`.
**This release** includes the unreleased work after that tag, through PR #70. `package.json` is `0.3.2`. Nisi is not published to the npm registry. This Release attaches `nisi-0.3.2.tgz` and `SHA256SUMS`.

## What changed

- The built-in Jev client uses Node's `https` module. `timeoutMs` may be from 1 second to 24 hours (default 60 seconds). v0.3.1 used global `fetch` and refused a timeout above 300 seconds; `fetch` also stopped a call after 300 seconds with no response headers. A `fetch` you pass to `createJevJudge`, `planWithJev`, or `createJevReviewer` is unchanged and keeps that limit. `planWithJev` and `createJevReviewer` pass `timeoutMs` through to that client when `judge` is `'typesafe'`. A `judge` function is used as is. The harder-task runner has `--jev-timeout-ms` for `--judge typesafe`; `--timeout-ms` stays the model-call timeout. The endpoint, request JSON, 1 MiB caps, and error codes are unchanged. Redirects are still errors. The key and the response body are still omitted from errors.
- The remote judge is opt-in. `planWithJev` and a review from `createJevReviewer` use the built-in client when `judge` is `'typesafe'`; a supplied `judge` function controls its own transmission. Reviewer construction sends nothing. `benchmarks/harder/run.mjs` calls it for `--plan` and `--jev-review` when `--judge typesafe` is passed. A `--judge` module still wins. In v0.3.1, advisor planning or review used the environment fallback when `TYPESAFE_API_KEY` was set and no judge was passed; the released harder-task runner required a judge module. The first unreleased runner change also used the environment fallback. With only that variable set, Nisi prints one stderr line (`TYPESAFE_API_KEY is set; the remote judge is off. Opt in with --judge typesafe or judge: 'typesafe'.`) and does not send. The advisor then throws `JEV_JUDGE_REQUIRED`. The runner exits before it creates the output file. A run without `--plan` or `--jev-review` stays on the local model and does not print that line. A `judge` other than a function or `'typesafe'` is `JEV_JUDGE_INVALID`. The line does not contain the key.
- A finished or partial harder-task file now records the token cap, timeout, reasoning effort, plan and review flags, task-set id, arms, repair budget (2), total deadline (600 seconds), judge source (`builtin`, `module`, or `function`), endpoint, package version, and Node version. It does not record the API key or the path of a judge module.
- A test reads `README.md`, `docs/benchmarks.md`, and `docs/local-models.md`. A table whose header contains accuracy, tokens/s, solved, or AUC must say `single run`, `runs:`, or `n =` in that section. Those three files have no such table missing the note. The package behavior is unchanged.
- `nisi validate` reads each journal and workflow report from one open descriptor (PR #57), opened with `O_NOFOLLOW` where the platform has it; Windows opens with `'r'`. The size limit is checked against that descriptor's `fstat`, and at most one byte past that size is read. In v0.3.1 a file that was within the limit at the `lstat` check and larger when read was read in full and could report `PASS`; it now fails with `FILE_TOO_LARGE`. A file that grows during the read fails with the new reason `FILE_CHANGED`. Where `O_NOFOLLOW` exists, a file replaced by a symlink after the `lstat` check fails with `SYMLINK`.
- `nisi validate` opens with `O_NONBLOCK` as well as `O_NOFOLLOW` where the platform has them (PR #60). A journal or report replaced by a FIFO after the `lstat` check made the open wait for a writer and `validate` hang. It now fails at once with `NOT_A_FILE`. Windows opens with `'r'`.
- The built-in Jev client reports a response body that stalls past `timeoutMs` as `JEV_TIMEOUT` (PR #54). It reported `JEV_RESPONSE_INVALID` before.
- `npm run check:cli-package` runs on npm 12 (PR #55). It accepts both the array and the object shape of `npm pack --json` and fails with a clear message on any other. The package is unchanged.
- `examples/workflow.mjs`, `examples/local-model-workflow.mjs`, `benchmarks/harder/run.mjs` and the four `benchmarks/value/` runners run when started through a symlinked path (PR #61). Through a symlink they printed nothing and exited 0.
- `reopen(serialized, {projectId, redactPaths, maxNow})` refuses a header that differs from what the host expects, with `PROJECT_MISMATCH`, `REDACTION_MISMATCH` or `CLOCK_AHEAD` (PR #62). One-argument calls are unchanged. It does not authenticate the journal; see [the review](../reviews/2026-11-14-journal-auth-review.md).
- The editable README clears stale backup warnings after a successful write (PR #51). Python scripts follow Ruff (PR #58); this changes no package behavior.

- Host-held journal anchors and harder journal reads (PR #66): `history/run-journal-anchor-v1.mjs` (import `nisi/history/run-journal-anchor`) implements review item R1. `readSerializedJournal` caps each descriptor read request at 1 GiB, reports `FILE_CHANGED` when the size changes during a read, and returns `REFUSED` with `READ_FAILED` or `EXISTING_INVALID` on UTF-8 conversion faults. `nisi validate` does not read an anchor. R2 (authenticating a writer) is not started.
- Docs (PR #68): `--tasks v2` is a separate 42-task set that replaces the default 16-task v1 set. The two share no tasks. Earlier wording ("42 more") could be read as adding tasks to the default set.
- Docs (PR #69): the Unreleased changelog recorded UTF-8 editor generation portability for `docs/editor/build-editor.py` (commit `52644b3`).
- Tests (PR #70): journal-anchor fixtures canonicalize the temp root with `realpathSync`. This is test-only. On macOS, `os.tmpdir()` is a `/var` symlink to `/private/var`, so hook path comparisons missed the product's realpathed paths and 29 tests failed. The product was already correct. After the fix, `npm run check` on the development Mac (Darwin arm64, Node v24.22.2) was 552 passed, 0 failed, 1 skipped.

## What was not verified

- No call was made to `https://api.typesafe.ai`. The transport tests point the request function at a local HTTP server. They wait a few hundred milliseconds under a timeout longer than five minutes. They do not wait five minutes, and they do not exercise the public TLS host.
- No local model was loaded for a Nisi run. The open roadmap item, re-measuring the harder tasks on a set or model with headroom, stays `NOT_RUN`. A 10 November 2026 check on the development Mac found four LM Studio chat models already on disk, including `qwen3.8-27b`, but no unauthenticated loopback chat-completions endpoint that Nisi can call. The previously used port 1240 was not listening. A new `lms load` was not started, because earlier loads on that machine had crashed LM Studio, and existing model-server processes were left running. `benchmarks/harder/run.mjs` and `examples/local-model-workflow.mjs` were not invoked. See [the 10 November 2026 note](../reviews/2026-11-10-live-model-remeasure.md). The 2026-11-07 result files were not regenerated. Those files still omit the token cap and timeout, so the published table rows cannot be repeated from the file alone.
- The two scratch journals from a revocation check are not in this repository. They were not re-checked on 10 November 2026. Their earlier read-only check was `INVALID_JOURNAL` from `nisi validate`, and `reopen` reported `INVALID` / `RECORD` at line 3 (seq 2, `retained: false`, state `REVOKED`) because the stored fingerprint does not match the stored entry. The hash chain was intact. Those files were written before v0.2.1, which pruned a row without recomputing its fingerprint. They stay rejected. `reopen` and `nisi validate` now name that case `LEGACY_UNRETAINED_FINGERPRINT`. The remedy is to run the work again with v0.2.1 or later. The old bytes were not copied in, and the file is not repaired.
- The one-PC Windows note is still the v0.3.0 note. It was not repeated on 10 November 2026. The current `.github/workflows/ci.yml` uses GitHub-hosted `ubuntu-latest` for Linux. Windows uses `[self-hosted, pc-win]` for pushes, manual runs and same-repository pull requests; fork pull requests use GitHub-hosted `windows-latest`. This routing does not establish a repeated hardware check or a passing CI result.
- npm registry publication was not done.

- Hosted CI still has no macOS job. Linux and Windows jobs on Node.js 22 and 24 are the required checks. The Mac result above was run on the development machine, not on GitHub-hosted macOS.
- On native Windows, at merge `b6a9110` and at this tag, the smoke-script test failed because it spawns `sh scripts/validate-real-data.sh --smoke` and `sh` is not on PATH (48 pass, 1 fail, 6 skipped). Named-pipe validation PASSES, and a link swap follows the new link as documented for Windows. This is test-only; the product is unchanged. After this tag, that test skips when `sh` is not available.
