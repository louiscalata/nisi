# Nisi v0.3.1 — release preparation notes

These are the notes written while v0.3.1 was prepared. The published text, including the checks run at publish time, is on the [v0.3.1 GitHub Release](https://github.com/louiscalata/nisi/releases/tag/v0.3.1). v0.3.1 was tagged and published on 9 November 2026. It is not on the npm registry.

**Source version:** 0.3.1, prepared 9 November 2026.
**Previous tag:** `v0.3.0` at `fb2c300c9d106f537b9efe9a584840d86ae02ca2`, published 7 November 2026 (2026-11-08 02:28 UTC).
**Commits after that tag:** #26–#31, plus the release-prep commit on this branch.

## What changed

- Built-in Jev client (`nisi/adapters/jev-client`). If `TYPESAFE_API_KEY` is set and you do not pass a `judge`, `planWithJev` and `createJevReviewer` send the task state to `https://api.typesafe.ai/v1/systemone`. v0.3.0 refused that call and sent nothing. A `judge` you pass still wins.
- Harder-task set v2: 42 generated tasks, `--tasks v2`. Default remains 16 tasks. `make_tasks_v2.py` reproduced the pinned file hash during this preparation. There is no separate prompt-only solver in the repository.
- Local-chat timeouts longer than five minutes work. The default transport no longer uses Node's `fetch` header timeout. An injected `fetch` is unchanged.
- Interrupted harder-task runs record the hash of the task set that was loaded. They were writing the v1 hash for a v2 run.
- `nisi validate` reads a journal file or a data directory and prints PASS/FAIL without payloads.
- Documentation was rewritten for a first-time reader (#26, #27, #31). The Jev speed comparison stays "no demonstrated gain": the 12.7 vs 15.4 minute gap is mostly one task both runs got wrong.
- Tests delete the temp directories they create. A Windows note for v0.3.0 on one PC is in `docs/verification-v0.3-windows.md`. It was not re-run for this version.

## What was not verified

- No Jev API call was made while preparing this version. Pre-analysis and post-analysis are `NOT_RUN` in `docs/jev/`. There was no `TYPESAFE_API_KEY`, no macOS Keychain, no Linux `secret-tool`, and no agiw-mcp consent file.
- No live model and no second Windows machine. The v0.3.0 Windows note does not cover v0.3.1.
- npm registry publication was not done.
- `~/.local/state/inference-monitor/fix-journal.jsonl` on the agiw-suite monitor is a different format (`inference-monitor.fix-journal.v1`). Pointing `nisi validate` at it should fail closed. It is not a Nisi run journal.

## Check real journals on the Mac

The repository fixture is synthetic. On the machine that has the journals:

```bash
git clone https://github.com/louiscalata/nisi.git
cd nisi
git checkout v0.3.1
npm ci
scripts/validate-real-data.sh --smoke
scripts/validate-real-data.sh --data-dir /absolute/path/to/your/nisi-data
# or one file:
scripts/validate-real-data.sh --journal /absolute/path/to/journal.jsonl
```

`--smoke` must print `"status": "PASS"` and `"passed": 2`. A real directory passes only when at least one `.jsonl` journal reopens cleanly, or one workflow report matches the report shape, and none of those records fail. Other JSON files are skipped. The summary does not include payloads. Exit 0 is PASS, 1 is FAIL, 2 is bad arguments.

`npm run validate:data -- --journal /absolute/path/to/journal.jsonl` is the same check without the shell wrapper.

## Tag and publish (done 9 November 2026)

1. Merge this branch. CI on the merge commit should be green (Linux and Windows, Node 22 and 24).
2. Tag that commit, not a later one:

   ```bash
   git checkout main
   git pull
   git tag -a v0.3.1 -m "Nisi v0.3.1"
   git push origin v0.3.1
   ```

3. Build the archive from that tag:

   ```bash
   git checkout v0.3.1
   npm pack --json
   shasum -a 256 nisi-0.3.1.tgz
   ```

4. Create the GitHub Release `v0.3.1` from these notes. Attach `nisi-0.3.1.tgz` and the checksum. Confirm `git clone --branch v0.3.1 --depth 1` then `node bin/nisi.mjs demo` prints the quick-start JSON.
5. npm publish stays a separate decision. Do not publish unless you intend to.

## Follow-ups

These were open when v0.3.1 was tagged. The published GitHub Release text was not edited.

- At release, the Jev client could not wait longer than 300 seconds, because it still used `fetch`. On main after the tag, the default transport is Node's `https` module. See the changelog Unreleased section.
- At release, `benchmarks/harder/run.mjs` required a `--judge` module. `TYPESAFE_API_KEY` did not drive that runner. On main after the tag, that runner briefly used the key when `--judge` was omitted. It now requires `--judge typesafe`. The key alone prints one line and sends nothing.
- Re-measure the harder tasks on a set or model with headroom. The open roadmap item from v0.3.0 still stands. This has not been run.
- Repeat the Windows hardware note if a v0.3.1 claim needs it. The one-PC note is still the v0.3.0 check.
- At publish, 23 of 25 journals passed `nisi validate`. Two nx05 revoke-scratch journals failed with `INVALID_JOURNAL`. Those files are not in this repository. The cause, found later from reason codes and line numbers only, is a pruned-row fingerprint left behind by a pre-v0.2.1 writer. See the run journal guide. The files stay rejected.
